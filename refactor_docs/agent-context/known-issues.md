# Known Issues

No implementation defect or failed check is asserted by this template. The target baseline, imported architecture and migration status remain unassessed. Missing evidence is not proof of success or failure.

## Entry template

- ID / Title / Affected components:
- Type: Defect / Compatibility risk / Dependency / Evidence gap / Recovery uncertainty
- Status: Open / Investigating / Resolved / Deferred
- Classification: Verified / Inferred / Unresolved
- First observed at UTC / Session:
- Evidence / Reproduction / Observable impact:
- Scope: Migration-related / Pre-existing / Unresolved
- Attempted resolution / Actual verification:
- Next action / Dependencies:
- Blocker Type / Stopped Session / Step ID / Brief Stop Reason:
- Intervention State: Not Required / Waiting for Human / Answered
- Required Human Decision / Resource / Approval:
- Options and Consequences / Recommendation (if applicable):
- Request / Response References / Time (when known):
- Human Answer / Approved Scope / Resumption Condition:
- Resolution evidence / Related sessions:

Record real findings at milestones. Mark missing history and uncertain change attribution explicitly during recovery.

Follow [human-intervention.md](../agent-rules/human-intervention.md) for escalation thresholds. Keep pending questions across sessions. Answered means the requested input arrived; it does not mean the technical issue is Resolved or verification passed. Never record a proposed/default option as human approval.

Human intervention stops all current-session development. Record the paused step in migration-status.md and link the detailed report; do not continue independent implementation tasks while waiting.
